# 巴拉鞋品专属模型识别

策略值 `bala_specialist`。通过现有鞋品任务配置选择，下载与最终图包导出仍走原脚本；本地子进程负责 DINOv2-S/14 分类、灰底配对、雪地鞋口定位和 OCR。模型缺失、身份冲突或品类未填写时明确失败，不调用大模型兜底。既有找图模式保留，默认选择「【推荐】巴拉鞋品专属模型识别」。

## 按需下载与安装

在「巴拉上新助手 → 【鞋品】整理深绘上新图包」选择「巴拉鞋品专属模型识别」，首次点击「下载并安装」。模型约 172 MiB，识别和 OCR 依赖另外下载。界面显示下载、安装、校验和已安装状态，支持取消与失败后重试。

主安装包只包含执行代码、下载清单和依赖锁，不带 DINO 权重、分类头、OCR 权重或 ONNX Runtime。模型从 `model-package.json` 中固定的抓虾 GitHub 提交下载，逐文件核对大小和 SHA256；依赖按当前系统的 `runtime-*-py312.txt` 安装到用户数据目录的独立 `libs`，不会改写应用 Python 环境。安装成功前会实际运行 224/448 DINO 和 RapidOCR，再原子发布安装目录。

安装位置为 Harness 用户数据目录下 `runtimes/bala-shoe/<平台>-<清单哈希>/`，用户无需选择模型或 Python 路径。已安装组件重启后复用，推理阶段完全离线；模型缺失或损坏时停止并提示重新安装，不切换大模型。

模型或依赖更新时同时更新 `model-package.json`（包括版本）和三平台依赖锁；清单哈希变化会使用新的安装目录。`app/build.yml` 明确排除 `shoe_specialist/assets/**` 和所有 `.onnx` 文件。开发训练工具继续在抓虾源项目维护。

## 输入与输出

- 款号品类表必须明确填写运动、休闲、婴童或雪地；204426146037 本轮按用户确认为婴童。没有将13款号/正确图片ID写入预测器。
- 推理输入只含图片来源、款号、色码、品类、文件哈希，拒绝标签字段。鞋盒 OCR 必须匹配完整12位款号及5位色码，并提供唯一款号文字框。
- TMZ1–4 优先使用前景像素、轮廓均一致的灰底源图；雪地 TMZ4/WPZ4 使用模板鞋口定位裁图。TMZ5 使用标准命名源图，WPZ15 选择同色灰底配对。
- 复用原脚本主推色、O、TMS、WPZ、YQ、YK、YX、渠道 PNG、TMQ、原图保留及最终导出规则；同名不同尺码照片绑定实际选中的路径，避免下载顺序覆盖。
- YX 使用独立的共用功能卡分类头（v3），包含单张浅色小卡片的补充样本；阈值读取权重元数据，保持0.5。分析记录保留模型哈希、阈值及前三候选。拒选只表示小模型未选中，报告保留待核验，不自动断言素材不存在。
- `专属模型选图证据` 记录实际源图哈希；不伪造多模型共识或大模型语义审核。

姿势分类头使用13款训练；YX分类头使用19款、31个款色的已复核样本训练。YX全量回放31/31，逐款留出开发验证30/31；浅色单卡仍是未见款的覆盖短板。这些回归不等于独立新款100%正确率。分类分数未校准，不是生产合格概率。当前整批错误会保留下载素材与分析目录并报错，不保证逐款容错续跑。

## YX 分类头复现

训练及导出仍使用抓虾源项目的 `scripts/train_shoe_yx_head.py`；Harness 仅提供已核准模型的下载与推理。训练产物通过实际 worker 回归后，在固定提交中发布资源并更新 Harness 下载清单。
