# 官方 Flash：DSH 新旧版本性能实测（2026-10-22）

结论：**没有测出整体提速。新版输入上下文更小，常规任务时延基本持平；启动、长上下文压缩和恢复更慢。** 短会话压缩成功次数更多，但不足以推广为统计性的可靠性结论。

## 测试设计

- 同机、同一本次用户授权的 DeepSeek 官方 key、同一 `deepseek-flash`（产品名 V4.1 Flash），reasoning=off。
- 旧版实际为 `0.1.2-rc.1 + pi-ai`，新版为 `0.2.1-rc.2 + Messages`。这是整套迁移效果，不能单独归因于内核或协议。
- 常规各 3 组，顺序 old→new / new→old / old→new；长上下文各 2 组，顺序 old→new / new→old。请求串行，无并发配额竞争。
- 每组独立 DSH_HOME 和产品数据；相同工作区、提示、截图。常规为文本→bash+read→read_image→手动压缩→read 续接。
- 长上下文为 160 行固定账本→库存查询→手动压缩→口令及库存召回。
- 计时从提交 prompt 前至 turn/end，包含模型、工具与本地 RPC，不是首 token 延迟。启动和压缩单列。
- 密钥由关闭回显的 stdin 注入，未写入脚本、报告或产品配置。未修改已有暂存区、安装应用和真实会话。

## 常规任务（各 3 次）

| 指标，中位数 | 旧版 | 新版 | 耗时变化 |
|---|---:|---:|---:|
| 短文本 | 0.918 秒 | 0.960 秒 | +4.6% |
| bash + read | 2.706 秒 | 2.841 秒 | +5.0% |
| 截图理解 | 1.974 秒 | 2.283 秒 | +15.7% |
| 每组前三项合计 | 5.755 秒 | 5.859 秒 | +1.8% |
| 运行时启动 | 1.339 秒 | 2.342 秒 | +74.9% |

正数表示更慢。“合计中位数”是先逐组相加再取中位数，不是三个中位数之和。

- 前三项每组耗时：旧版 5.818 / 5.289 / 5.755 秒；新版 5.075 / 5.859 / 6.169 秒。
- 两版各 12/12 用户轮次成功；其中压缩前任务各 9/9 通过。工具任务同时检查实际 bash/read/read_image 调用；截图回答核对 P0 内容。
- 短会话压缩：旧版 **1/3**，新版 **3/3**。旧版两次返回“无法生成有效摘要，原会话不变”。后续回答正确不等于压缩成功，因此不把两版这部分续接时延作为严格同条件对比。
- 短会话只有约 800 token 历史，压缩策略和摘要收益判定也可能造成差异，不能仅凭此判断旧版普遍不稳定。

## 输入 token（压缩前的 9 个相同用户轮次合计）

| 指标 | 旧版 | 新版 | 变化 |
|---|---:|---:|---:|
| 非缓存 inputTokens | 25,315 | 6,797 | -73.2% |
| cacheReadTokens | 97,920 | 103,808 | +6.0% |
| 输入总量：非缓存 + cache read | 123,235 | 110,605 | -10.2% |
| outputTokens | 751 | 747 | -0.5% |

旧版 mapUsage 明确省略值为 0 的缓存字段。本轮仅三个无工具短文本轮次缺 cacheRead，每轮一个模型回答，可按 0 计入此表；原始 JSON 保留 null。未将所有未知指标统一当成 0。

**更可信的观察是输入总量少约 10.2%。非缓存输入少 73.2% 同时受服务端缓存命中影响，不能当作稳定成本降幅。** 服务端缓存无法清空；交替顺序只能减少顺序偏差，不能消除缓存与时段影响。本轮没有核实单价、推算账单；手动压缩内部调用的 token 不在本表，也不代表完整流程总成本。

## 长上下文补测（各 2 次）

160 行固定账本，实际压缩约 4,886–4,981 个历史 token。两版均 **2/2 压缩成功**，后续均准确召回 `LEDGER-7319` 和库存 `1124`，用户轮次各 6/6 成功。

| 指标，两次中位数（即平均值） | 旧版 | 新版 |
|---|---:|---:|
| 账本输入确认 | 1.409 秒 | 1.165 秒 |
| 库存查询 | 0.974 秒 | 0.645 秒 |
| 手动压缩 | 2.377 秒 | 3.227 秒 |
| 压缩后召回 | 0.587 秒 | 1.285 秒 |

新版这组输入确认和查询较快，但压缩与恢复较慢。两次样本只能说明实际观测，不能确定根因。没有把短会话失败算成成功，也没有重跑已完成样本挑选更好的数字。

## 判断与建议

升级的确定价值仍是运行时能力与兼容性：Messages、动态工具、持久 PTC、生命周期等；本轮还观察到较小输入预算。**不建议以“明显提速”作为升级宣传。** 后续优先分析新版启动、摘要策略及压缩后首轮缓存重建，再扩大真实业务长任务和 high 思考模式样本。

本轮是小规模 smoke，不提供显著性、并发吞吐、p95 或全面成功率保证。输出长度不是完全相同；未重新验证打包桌面点击操作或高思考模式，也没有把本轮结果外推到其他模型。
