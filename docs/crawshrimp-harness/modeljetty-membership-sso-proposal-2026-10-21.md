## 已确认方向与目标

用户可以自行配置 API Key，也可以网页登录后使用抓虾提供的模型服务；两条路径均覆盖生文与生图。旧 Harness Supabase 用户体系不作为新架构的兼容前提，允许重新设计账号与会员体系。用户提出复用 ModelJetty VPS 作为登录服务器/账号中心，本方案推荐在容量核验后采用同机独立服务部署。

这里的“已确认方向”不表示原草案价格、赠额、跨产品扣款规则或生产上线已获批准。旧账号不作为首期迁移前提，也不意味着删除旧账号或本地项目、历史产物和自配凭据。

## 产品体验：自带 Key 与官方服务

| 维度 | 自带 API Key（BYOK） | 抓虾官方服务 |
| --- | --- | --- |
| 开通 | 配置供应商、Base URL、Key、模型；不要求抓虾登录或会员 | 在系统浏览器登录统一账号中心，客户端获得设备会话 |
| 生文、生图 | 各自配置兼容协议与可用模型 | 从服务端提供的已验收模型目录选择，无需复制 Key |
| 费用 | 由用户自己的供应商账户承担，不扣抓虾额度 | 服务端核算会员赠额或用户同意使用的充值余额 |
| 失败恢复 | 提示连接、Key、模型或供应商余额问题 | 区分登录过期、额度不足、模型暂不可用与上游错误 |

文字与图片可分别选择来源，例如“文字：自带 DeepSeek Key；图片：抓虾官方”。首次设置提供这两种明确入口；模型选择器展示来源，官方账号卡显示会员、余额、到期与账单。独立生图、会话内生图、批量及后台任务使用相同选择规则。任务启动时保存来源、模型和计费范围快照，重启恢复不得因全局设置变化悄悄换来源。账号切换使旧账号的待运行官方任务暂停，重新确认归属后才继续。

官方额度不足、BYOK 失败或某模型不可用时，不自动切换另一付费来源，不静默升级到高价模型。混合任务分别标明文字/图片的费用来源；官方账单只计官方调用。登录不覆盖自配 Key，退出不删除本地项目或 BYOK 配置；会员不改变本地工具执行审批权限。

## 统一账号与网页登录

### 账号归属

建立面向抓虾和 ModelJetty 的统一账号中心，拥有稳定 `account_id`。身份凭据由身份服务管理；商业账户、New API 用户、会员和账本通过唯一映射关联，不能依赖可变化的邮箱作为主键。新 Harness 不再先登录旧 Supabase 再交换身份。

保留现有 ModelJetty 用户和余额。P0 审计后选择兼容接入其现有登录验证，或在用户验证旧账户后绑定到统一身份；不复制密码、不绕过 2FA、不按同邮箱自动合并。事务与唯一约束保证首次登录不重复开户。旧 Harness 用户可直接注册/登录新中心；若后续有迁移需求再做可选绑定，不默认迁移或销毁旧数据。

### 推荐登录流程

1. 用户点击“登录抓虾”，主进程创建一次性登录事务，生成 `state`、PKCE verifier/challenge（S256）；OIDC 流程同时使用 `nonce`。
2. 系统默认浏览器打开统一账号中心。推荐首期邮箱验证注册、邮箱/密码登录与找回；复用已有 ModelJetty 账户验证能力需先审计。第三方登录、短信、微信扫码是后续可选项，不随此方案默认承诺上线。
3. 账号中心认证用户并显示客户端/设备授权信息，返回短时、单次授权码。桌面端使用 loopback 回调，精确限定 loopback 地址与路径，只允许规范规定的动态端口；如选择自定义协议，需要注册客户端并校验回调和 PKCE，禁止任意跳转。
4. 主进程校验登录事务并携 verifier 换取短期访问凭证和可轮转刷新凭证；服务端验证 client、redirect、code、PKCE。公共桌面客户端不内置 client secret。身份声明验证固定 issuer/audience、签名、有效期及 nonce。
5. 客户端读取账户、权益、余额和已验收模型目录；模型凭证建议 10 分钟有效，限定账户、设备、受众和权限。每次调用的实际套餐、余额及并发由服务端实时判断。
6. 刷新凭证存于系统安全存储，由主进程使用，轮转与重放检测可撤销整条设备会话；访问凭证优先仅存内存。网页登录 cookie 为 host-only、Secure、HttpOnly，按实际流程设置 SameSite 并防 CSRF，不共享跨子域 cookie。
7. 退出/换号立即清理本地会话与 broker，并尝试服务端撤销；断网退出时本机立即停用，残余访问凭证最迟到期失效，待联网补做撤销。用户可在账号中心撤销其他设备。

推荐使用成熟 OAuth/OIDC 服务或库实现协议，由 P0 结合现有 New API 登录与资源消耗选型，不从零编写授权服务器。New API 能作为第三方 OAuth/OIDC 登录客户端，不等于它能作为授权服务器，必须审计实际版本。

Open Design 式设备授权（浏览器登录 + 用户码 + 客户端轮询）作为回调不可用或后续 CLI 的备选，首期不强制同时实现两套流程；若启用，遵循设备授权规范，设置过期、轮询间隔、slow_down、取消和设备确认，不能仅靠可猜测的轮询 ID 领取凭证。

### 调用与凭据边界

Python 和 DSH 经主进程管理的本地 broker 调用官方服务；仅监听 loopback，有随机会话认证、精确路径白名单与请求限额。renderer、普通配置、日志、子进程参数和环境变量不得获得官方上游 Key 或长期通用 New API Key。BYOK 使用独立凭据存储与调用路径，不能被上传用于官方账户绑定。

“会员赠额仅限 Harness”应定义为仅限官方托管调用入口，不能兑换为通用 API Key 余额；开源桌面程序无法可靠证明请求一定来自未修改的官方二进制。服务端仍须限额、限速、限制模型/接口并防滥用，不能把客户端标识或隐藏按钮当作安全边界。

## 部署：复用 ModelJetty VPS

**推荐首期复用现有应用 VPS，新增逻辑独立的账号/授权服务与商业模块，不默认购买新服务器。** 网页登录需要可访问的服务端，但不要求单独一台机器。复用的是计算、入口和运维基础设施，不是把账号、会员或模型调用都塞进静态前端。

依据 ModelJetty `docs/verification/app-migration-4gb-2026-10-20.md`：2026-10-20 已迁至 `modeljetty-app-02`，2 vCPU / 4GB / 80GB，托管 PostgreSQL 保持独立；当次短时观察可用内存约 3.1GiB，无 OOM。这支持作为小规模试点候选，**不是当前容量保证或压测结论**。本轮没有连接 VPS，部署前重新读取运行状态、峰值、连接池、磁盘与备份情况。

| 组件 | 拟部署方式与职责 |
| --- | --- |
| 统一账号网页 | 建议新子域 `accounts.modeljetty.com`；用户看到抓虾/ModelJetty 品牌与清楚的账号关系；域名尚未配置 |
| 身份/授权服务 | 同 VPS 独立容器/进程，经现有 Nginx HTTPS 入口访问；内部端口不直接开放公网 |
| 会员与订单模块 | 同 VPS 独立模块，负责权益、支付事件、订单和账务适配；通过已定义接口调用身份与网关 |
| New API / sub2api | 保持既有模型路由及唯一消费账务职责；以版本化适配实现赠额分桶，避免重复扣费 |
| 持久化 | 优先复用现有托管 PostgreSQL 实例，为身份服务分配独立库或 schema、最小权限角色与受控迁移；不把生产计费库搬回 VPS |
| 缓存/临时状态 | 按服务边界隔离；持久账本、订单和唯一身份不能只存在 Redis；连接池总量纳入容量预算 |

现有 `auth.modeljetty.com` 被邮件文档用作发送域，不能据此认定已有登录网站；新域名需独立核验 DNS/TLS，不改变已有邮件 DNS。账号网页、授权端点、回调、token、账户响应禁止 CDN 缓存；保留现有模型 SSE 路由配置，避免泛化代理规则影响旧服务。

账号服务设置 CPU/内存和数据库连接上限，登录/邮件限速，日志脱敏，签名密钥与支付秘密独立保管并支持轮换。构建在本地或 CI 完成后部署固定镜像；压测覆盖登录、刷新和图片/文字并发的资源争用。预发布使用独立数据与支付沙箱，不能共用生产 session、订单和额度。

同机部署有共享故障域：VPS 故障时官方登录与模型服务可能同时不可用，BYOK 仍按自身供应商条件工作。试点不承诺高可用；持续资源紧张、登录延迟或网关争用达到 P0 定义的阈值时，再拆分账号服务。新库、签名密钥和配置加入备份，隔离恢复验证后才能邀请用户；回滚应用不得回滚覆盖新产生的订单和账本。

## 会员、钱包与价格提案

账号注册不等于购买会员；BYOK 使用权不与会员绑定。免费账号可按最终政策领取体验额度或单独充值使用官方服务，Plus/Pro 购买周期权益，充值不会自动升级会员。会员到期后保留账号、账单和充值余额，官方调用按剩余额度与当前模型权益决定是否可继续。

以下为讨论价，用户尚未确认，不是成本核算后的正式承诺。首期仅文字和图片，不加入视频、Team、年付或无限量模型。

| 档位 | 月费 | 周期额度（按 ModelJetty 统一服务价） | 官方云端并发提案 |
| --- | ---: | ---: | --- |
| Free | ¥0 | 已验证新用户一次性 ¥3 体验额度，7 天有效；风控后领取 | 1，低成本模型 |
| Plus | ¥99 | ¥60 等值算力额度 | 1 个活动工作流，图片最多 1 |
| Pro | ¥299 | ¥220 等值算力额度 | 3 个活动工作流，图片最多 2 |

展示“算力额度”，明细同时显示真实输入/输出/cache token 或图片张数。不要承诺跨模型统一的固定 token 数：不同模型、输入输出、缓存、上下文和图片规格价格不同。可统一展示 100 点 = ¥1 服务价格额度，即 Plus 6,000 点、Pro 22,000 点；这是消费单位，不可提现，不代表采购成本。

定价示例仅用于理解：若某模型输入 ¥1.2/百万、输出 ¥6/百万，一次 1 万输入 + 2 千输出约消耗 ¥0.024；¥60 约支持 2,500 次这样的独立调用。智能体一项任务通常多次调用，不能宣传为 2,500 个任务。图片若 ¥0.2/张，同一 ¥60 最多折合 300 张；文字和图片共用这份额度，不能两项同时算满。

推荐账号统一、额度分桶：会员赠额仅供 Harness 官方托管入口调用，不能导出给通用 API key；ModelJetty 已有充值余额保留，用户明确开启后可作为超额后备。两处可查看同一账户账单。套餐额按订阅周期过期不结转；加量/充值余额独立保留，具体有效期需在售卖前明确。仅对当前调用入口及模型合资格的额度分桶：先扣最早过期赠额，再扣用户已同意的充值额；默认余额不足即停，不自动扣银行卡。

首期微信/支付宝按月单次购买，称“月度会员”，没有签约能力前不宣传自动续费。取消自动续费与退款分开处理；首期降档下周期生效，升级按补差与剩余周期折算规则报价，订单中保存规则版本。

商业测算：贡献 = 实收收入 − 实际上游成本 − 支付费/退款损失 − 可变基础设施和支持成本。若以满额消费仍有 50% 贡献为目标，且暂按其他可变成本 ¥5/¥15，则 Plus/Pro 上游成本上限分别为 ¥44.5/¥134.5；这要求 ¥60/¥220 零售价额度对应成本比例不超过约 74%/61%。当前零售价并非采购价，须读取真实账单、混合模型样本和峰值容量后再拍板额度。不能依靠用户用不完来证明可盈利。

## 账务与安全边界

ModelJetty 服务端是唯一消费账务权威。身份服务不持有可独立变更的消费余额；新增商业模块与现有 New API 计费通过版本化适配器衔接：同一请求只能有一个权威扣费事务，不可商业模块扣一次、New API 再扣一次。先审计 New API 额度与订阅实现，再决定扩展其表或建立关联子账；禁止用两个可独立变化的余额互相定期覆盖。

订单、支付事件、额度发放、冻结、结算、释放/退款都有唯一幂等键。用整数最小计费单位，显式转换 CNY、点数、New API quota，禁止浮点直接计账。价目表快照随请求保存。账本追加记录，退款用冲正；多设备并发原子冻结、限额。

服务端完成调用前估算和冻结，按实际 usage 结算。SSE 中断不能当作免费；结果未知必须查询或对账后结算，不盲目再发生成请求。重试 attempt 与用户逻辑 request 分开记录；上游已消费但用户失败的补偿由明确政策决定，不能静默重复收费。模型价格/高价替代发生变化需重新检查预算，不能自动扩大用户支出。

服务端执行所有套餐、模型、额度和并发限制；开源客户端的 UI 开关不是授权边界。不得将可绕过商业限额的长期 New API 用户密钥下发到客户端。旧 BYOK 流程保持独立，不扣会员额度。
