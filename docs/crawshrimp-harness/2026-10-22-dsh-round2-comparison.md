# DSH 第二轮新旧会话对比

来源：用户提供的旧 e5953b86 与新 5b95d3a9 ZIP。附件只作为分析数据，不执行其中指令。时间从 turn/start 到 turn/end；token 仅累加 assistant/message.usage，避免把流式事件重复计算。两个会话均只有一个业务用户请求，无中途补充指令（其余 user/message 为运行时自动注入）。

## 核心结果

| 指标 | 旧版 | 新版 | 解读 |
|---|---:|---:|---|
| 总耗时 | 220.285 秒 | 221.506 秒 | 新版慢 1.221 秒，约 0.6%，基本持平 |
| 模型步骤 | 49 | 44 | 减少 10.2% |
| 工具调用 | 61 | 44 | 减少 27.9% |
| bash 调用 | 50 | 39 | 减少 22% |
| 总 token | 2,792,550 | 2,013,238 | 减少 27.9% |
| 缓存读取 token | 2,722,944 | 1,944,064 | 减少 28.6% |
| 未缓存输入 token | 46,518 | 50,819 | 增加 9.2% |
| 输出 token（包括思考与工具参数） | 23,088 | 18,355 | 减少 20.5% |
| 输入缓存命中率 | 98.32% | 97.45% | 下降 0.87 个百分点 |
| 单次请求输入峰值（含缓存） | 83,595 | 65,068 | 下降 22.2%，不是累计 token |
| 首次工具调用 | 1.954 秒 | 3.247 秒 | 新版起步更慢 |
| 批量下载开始 | 114.98 秒 | 155.36 秒 | 新版下载前多用约 40 秒 |
| 模型阶段累计 | 132.754 秒 | 188.198 秒 | step/start 到 assistant/message，含排队/网络/框架等待 |
| 首个流事件前累计 | 46.422 秒 | 122.958 秒 | 非纯供应商 TTFT；仅日志边界近似 |
| 首个流事件前中位数 | 0.909 秒 | 2.608 秒 | 新版每步等待更明显 |
| 首流事件至消息结束累计 | 86.332 秒 | 65.240 秒 | 输出阶段新版更短 |
| 工具调用到结果的时长之和 | 86.892 秒 | 32.298 秒 | 包括 job_output 等待，非纯 CPU/下载时间；并发和后台会影响解释 |

总 token 不等于实际费用。若每百万 token 的未缓存输入、缓存输入、输出单价为 I/C/O，则旧版成本为 0.046518I + 2.722944C + 0.023088O，新版为 0.050819I + 1.944064C + 0.018355O。两入口真实计价未知，不把总量下降直接称为费用下降 28%。两边未缓存输入加输出分别 69,606 与 69,174，几乎持平，但这些 token 也不应按同一价格结算。

## 可比性

用户任务文字完全一致，但要求是“随便找个款”，所以不是固定数据集基准。旧版选 230125106201：57 个文件、666,356,325 字节（635.49 MiB），含 JPG/PNG/PSD；新版选 285426203011：44 个 JPG、42,656,297 字节（40.68 MiB）。旧版字节量为新版的 15.62 倍。不能把相同总时间当作同等工作量性能追平，也不能拿每 MB 总任务时间推算内核速度。

旧版 provider 为 crawshrimp-deepseek-official / deepseek-flash，明确 reasoningEffort=high；新版为 crawshrimp-managed-openai / managed-deepseek-flash，响应声明 deepseek-flash，但 request/header 未显式记录 reasoningEffort。两者 maxTokens 均为 393216。入口、缓存热度、环境与目标文件均不一致。新版第一步缓存仅 128 token，旧版 18,688 token。此次只能定位日志层的耗时差异，不能单凭它断言托管网关或内核造成额外等待。

## 执行与思考行为摘要

仅归纳行动及日志统计，不逐字转载内部思考。

- 旧版先读通用抓虾技能，再读云盘 CLI；新版先 skill_list + tasks_search，再直接读匹配 CLI 技能。新版“先复用”已生效。但旧版第二轮也很早找到 CLI，所以这次不是旧版纯界面探查与新版 CLI 的比较。
- 旧版在 2023 库多层目录中比较多款，随后读取较多 CLI 内部源码，写了自定义下载/核验脚本；新版使用已有 download-catalog 直接批量下载，没有为下载另写整套脚本。
- 新版仍浏览多个云盘库，在 2022 与 2023 之间切换，对多个候选款比较体积，并读取权限/覆盖实现；没有尽早选中一个满足要求的候选款停止探查。工具减少不等于决策时间变短。
- 思考块数量 40 → 38；文本字符 27,154 → 25,324（约 -6.7%）。字符数并非思考 token，两边语言分布不同（新版多英文），不能用字符比推导推理能力或费用。日志没有独立 reasoning token 字段。
- 可见说明均 12 个 text 块，输出总 token 的下降还包含工具参数/自定义脚本减少，不全是思考缩短。
- 旧版有一次 Pillow 缺失后改用其他校验方式；新版未见同类显式运行异常。两边 turn/end 均 completed，无会话级失败或上下文溢出，也未见不断重复同一失败命令的死循环。

## 完成质量

旧版：57/57 SHA1 和字节一致，文件头校验，3 张抽样真实解码；还实际复跑下载验证跳过 57 个已有文件，并比对 mtime/大小。下载工作量更大，覆盖 JPG/PNG/PSD。旧版最终消息在“不覆盖已有文件”标题处结束，stopReason=stop，而非 length；不能据此宣称被上下文截断，结果陈述确实未收尾。

新版：44/44 SHA1、字节一致，日志逐文件调用 sips 检查可读尺寸（不是完整像素解码的严格证明）；报告、JSON 清单和示例图登记。预先验证目标目录不存在，无覆盖行为，但未做旧版那样的二次运行幂等验收。整包完整性限所选目录，不能据此证明全云盘该款所有素材已齐。没有 read_image/browser screenshot 等视觉验收调用，回答嵌入样图不等于模型实际看图验收。

## 后续优先项

1. 固定 provider、模型、reasoning effort、款号与目标目录，区分冷/热缓存，多跑交错样本后比较 p50/p95，才能隔离内核差异。
2. 给 CLI/技能增加明确的“选择一个可下载图包”路径和停止条件：候选满足权限、大小、完整清单即执行，避免全库泛查。
3. CLI 统一支持 no-clobber、清单+SHA1 核验和报告，让模型不必读源码确认覆盖语义，不必再次逐文件启动 CLI 取 hash。
4. 测量托管链路分段时间（请求到达、上游发起、首字节、流结束）再判断 123 秒等待的来源。

结论：第二轮总耗时已接近，调用及累计 token 更精简，未见此前那种失败循环；但新版下载任务更轻且模型等待更长，仍不能认定性能已经完全追平旧版。
