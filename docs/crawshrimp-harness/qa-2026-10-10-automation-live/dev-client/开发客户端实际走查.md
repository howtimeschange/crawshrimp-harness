# 开发环境客户端实际走查

2026-10-10，抓虾 Harness 源码开发客户端。当前结果仅适用于开发环境，未打包、发布或替换安装版。

## 最终实现

普通定时任务默认把目标追加到创建它的固定会话，沿用会话当前模型、工具、工作区和访问模式，不另设自动化白名单；显式专用会话也持续复用一个执行会话。已有脚本可以从任务中心配置每天/每周直接运行，保存参数与运行记录，不必每次调用模型。旧的 scoped 和闭环 Program 保留兼容。

会话模式接续时，worker 采用 DSH 已保存的 native session 工作区归属；若当前 Host 已 ready，则复用当前 Host，不因来源会话模型与启动默认 route 不同而重启。接续 payload 标记 `sessionContinuation`，让 native 会话使用自身步骤/工具预算；调度超时和输出保护仍保留。读取 live native 模型选择时，在 provider/model 未变时保留原 reasoning effort。HTTP 显式 `context_mode=isolated` 的 session 任务可不带来源会话创建专用执行会话；未显式 isolated 的普通 session 任务仍默认 inherited，并要求现存 source。

普通 assistant 回答完成只代表本轮执行结束，不伪造外部业务 `verified=true`。严格验证 schema 仍保留证据要求。

## 客户端走查发现并修复的问题

1. 17:11 的旧 scoped 首轮失败：模型只配置 read_only，但滚动工具归类 local_write。此为 `AUTOMATION_POLICY_DENIED`，没有审批卡。旧任务通过 UI 暂停，失败记录保留。
2. 按用户新建议改为 session 默认模式。整合审查修复 controller 未传模式 metadata 导致普通完成仍被旧验证规则阻断的问题；同时保留超时为独立非权限 metadata。
3. 17:43 实际客户端创建时，模型只填 `execution_policy={timeout_seconds:600}`，被错误归为 scoped。任务 `2168a3d88eeb4b039e30ed6c938837cf` 在首轮触发前经 UI 暂停，没有运行。共享默认推断现已修正：仅超时、重试、等待或 schema 的普通策略默认 session；显式旧权限字段（包括空 toolset）仍兼容 scoped。HTTP API 也修正了 isolated/session 创建边界：显式 isolated 不再要求 source，同时仍禁止 HTTP 任意绑定 source；inherited 分支继续严格校验现存 source。新增 MCP、Controller、HTTP 契约测试并重跑 Python 全量。
4. 17:54:55 的 session 首轮在模型调用之前失败。DSH 明确报告同一个 runtime session 属于来源聊天工作区，而 worker 错传了默认 `agent/runtime-workdir`。工具调用与审批均为 0，不能归因于权限不足。服务层还遗漏了无 `summary` 的 worker 错误响应，已补响应契约归一化，防止错误落库为字符串 `"null"`。
5. worker 现按 DSH 保存的会话归属接续原工作区，新会话默认使用统一 `agent/workspace`；不轮换原 SID。读取 live native 模型选择，在 provider/model 未变时保留已有 reasoning effort；generation readiness 比较 provider 与真实模型名，避免别名差异导致重启。补了工作区归属、模型选择、错误响应及取消过程契约测试。
6. 18:14:55 接续后的自然轮次 `418fa720badd4ef992ce80bc8d3a10b6`，Agent `run-249f0a74ec4f`，已实际执行 29 次浏览器工具调用、0 次审批，读取了公开嵌入帖；但 worker 误套默认 30 步交互预算，在最终回答前以 `BUDGET_EXCEEDED` 中断。任务经 UI 暂停。后续修复已让 session-mode 在 worker ready 时复用当前 Host，并在 worker payload / retry payload 标记 `sessionContinuation`，由 native 会话使用自身步骤/工具预算；调度超时和输出保护保留。此次中断也不计为验收成功，真实两轮接续验证另行执行。
