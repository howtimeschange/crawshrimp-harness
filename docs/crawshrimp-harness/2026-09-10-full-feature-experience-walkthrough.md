### G01 — 工作台左边界错位

**复现**：收起导航 → Cmd+R 刷新 → 等待客户端恢复 → 首次打开 AI 生图。任务中心也出现同类现象。不是每次折叠都会触发，关键在折叠状态下刷新后的首次进入。

**实际**：导航实际宽约 54 逻辑像素，工作台却仍从约 270 像素处开始，中间露出底层历史聊天和输入区。用户提供的红框截图与复现现象一致。

**预期/影响**：工作台应始终贴齐实际导航边界。当前混合显示两个页面，影响空间利用和操作理解。

用户提供的红框原图保存在本地 QA 工作区。

**临时恢复**：展开导航，再收起，可恢复贴齐；再次刷新仍可复现。

**排查方向**：`App.vue` 的 `railWidth` 初始值 280、`onRailMetrics`、`embedLeft`；`AgentWebView.vue` 的 fallback、bridge-ready 与 rail-metrics 同步时序。尚未证明唯一根因。

**关闭条件**：展开/折叠两种状态，刷新、恢复启动、工作台来回切换后，生图与任务中心均与导航贴齐，无底层正文露出。

### G02 — 空 Prompt 遗留虚假运行态

**复现**：新建生图任务，Prompt 留空，点击开始；随后编辑名称/Prompt触发自动保存。

**实际**：上下区域出现 `Error invoking remote method 'run-ai-image-job': Error: AI image job prompt is required`；删除被禁用并称任务生成中。前端先写 running，异常后没有恢复；后续自动保存可将虚假状态持久化。恢复客户端后也观察到自动保存再次写回 running。

**预期/影响**：空输入应在提交前以中文就地校验，不创建运行态或占用删除/操作状态。用户难以区分校验失败与真实生成中。

**证据边界**：测试任务 `a439a724e5b14029842162956ffd8ea9` 后来填写正常 Prompt，真实生成成功并恢复完成状态；不能用收尾数据库的 completed 反推异常未发生，也不能说该任务现在仍卡住。

**排查方向**：`AiImageWorkbench.vue` 的 generate、autosave、异常处理；`core/ai_image_service.py` 的 `run_job_with_one_xm` 在构建请求时抛出空 Prompt 错误。

**关闭条件**：空白/纯空格 Prompt 均阻止提交；失败后状态与按钮正确；跨页、自动保存和重启不产生虚假 running。

### G03 — 输出文件跨运行混合

**复现**：同一任务实例先跑无匹配款号，再跑正常款号，之后启动并立即停止一次任务。

**实际**：run14 显示“已停止，保留0条结果”，数据库 `output_files=[]`；输出面板仍列出 run12 的 Excel 和 run13 的 ZIP、Excel 共3个旧文件，无清晰 run 归属。

**预期/影响**：本次运行结果应只展示本次产物；历史产物如需保留，应明确分组标注。当前容易误把上次结果当成当前下载结果。

**证据**：本轮只读核对确认停止的运行有 0 条记录、无输出。上一次运行自然完成。

**排查方向**：`TaskRunner.vue` 的 `ensureTaskInstanceForRun` 复用实例，`refreshOutputFiles` 合并实例 artifacts 与 summary.output_files，缺少运行级归属过滤。

**关闭条件**：成功→无匹配→停止→再成功，逐次结果与 run ID、数据库、输出文件完全对应。

### G04 — 新运行继承旧进度与日志

**复现**：完成一次无匹配查询后，在同一实例中改用有效款号，再重复启动。

**实际**：新运行刚开始仍显示旧款号、100% 进度；另一次显示上轮“下载完成2/2”。旧日志也保留。随后新事件到达才更新。

**预期/影响**：本次运行开始即显示初始化状态和当前输入，历史日志应明确分隔，避免误判已完成或执行了错误款号。

**排查方向**：`TaskRunner.vue` 的 `resetRunUi`、`applyLocalLiveStatus` 以及 `props.task.live` 旧快照合并。

**关闭条件**：重复执行与改参数执行，新 run 首帧不显示前 run 的目标或完成百分比。

### G05 — 图片下载无反馈

**复现**：选中生图原图与修改图，点击下载选中，在原生弹窗选目录。

**实际**：无可见忙碌/进度/完成提示，按钮仍可点击；磁盘文件逐步增长，开始只有一份未完成文件。最终两张均完整下载、可解码，为2880×2880 PNG。

**预期/影响**：提示下载中、完成数量和保存位置；避免重复提交。此项是反馈缺失，**不是下载失败或图片丢失**。

**排查方向**：`AiImageWorkbench.vue` 的 saveAs，完成后写 logs，但当前界面没有可见日志反馈与 downloading 状态。

**关闭条件**：大文件下载期间有明确反馈，完成后可确认两份文件；失败时指出失败项并可重试。

### G06 — 零匹配摘要不够明确

**复现**：用一个已知无匹配的款号执行云盘脚本。

**实际**：绿色“完成，共1条记录”，日志无醒目的未匹配业务摘要。Excel 如实记录“未匹配到图片”“搜索结果3条，过滤后0条”，无图片包。

**预期/影响**：区分执行完成、匹配图片数与结果记录数，例如“完成：下载0张，未匹配1个款号”。当前必须打开 Excel 才能理解业务结果。

**证据**：该次运行状态为 done，结果表只有 1 条未匹配记录。

**关闭条件**：全未匹配和部分未匹配均在结果摘要展示匹配/未匹配统计。

### G07 — 标注区生产许可提示外露

**复现**：打开生成图大图，进入标注区域。

**实际**：右下角可见 `Get a license for production`，AX 同样可读。

**预期/影响**：最终产品不应外露第三方 SDK 的开发/许可提示，影响成品感。这里只确认提示存在，未核实许可证状态，不作法律违规判断。

**关闭条件**：按 tldraw 正规配置核实发布环境，最终安装包中不再出现该提示，标注功能仍可用。
