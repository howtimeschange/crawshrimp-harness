## 实施策略

对现有文件使用固定源父提交作为三方比较基线，在临时目录生成候选差异后逐段复核；不对仓库执行整包覆盖或cherry-pick。新增共享组件按明确文件迁入，共用大文件中的账户、MCP、任务隔离和自动产物交付保持目标版本。

首轮候选合并在主进程、工作台、设置、图片服务等处发现重叠，需语义处理；尤其设置中的智能体运行时/账户控制不能因源项目不存在而被删除。源常量中残留的GPT2.5不迁入。

## 本轮验收计划

先执行输入边界/快照/并发失败/字段匹配/版本/换脸并发与权限的针对性回归，再使用隔离源码Electron验收热配置、输入保留、Finder拖入和排序、只读预览、天猫审批换脸。真实供应商调用、模拟故障和换脸视觉质量分别记录，不沿用先前验收计数。

不提交、推送、部署、发布或外发消息。凭据只从授权本机配置读取，日志和报告不包含Key。

## 本轮真实发现并修复

1. `waiting_generation_confirmation` 未纳入任务中心当前/待处理列表，导致天猫任务消失；补齐后实际任务已重新显示。
2. 并行完成的工作台轮次可能覆盖历史结果；在任务锁内读取最新 summary 后追加。单轮失败返回不再被历史成功掩盖。
3. 新建任务的异步窗口可能将空表单写入上一任务草稿；保持恢复保护直到新任务创建完成。
4. 审批批次每次从整个源码目录递归查找，拖慢本机服务；优先运行数据目录，缓存已找到路径，同时保留旧目录兼容。
5. 森马网关在大图上传中途返回 429 时，标准上传只暴露 Broken pipe；现读取同一连接的提前回执，不重新发送 POST。回执正文中断仍保留已经收到的 HTTP 状态。
6. 天猫同步供应商单条多图拆成受限并发调用，保留成功图片和失败明细；未知回执单独记录并阻止整批重复提交，运行中的批次也拒绝重复提交。
7. 换脸期间其他调用保存的审批在后端已保留，但旧前端状态可能再次覆盖；改为字段差量保存和完成后刷新合并。生图进度不再误用创建测图任务的成功计数。
8. 开发桥接补齐 run 快照透传；preload 的 HTTP 回退为生图与换脸提供 20 分钟等待窗口。
