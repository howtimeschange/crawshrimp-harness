# DSH 升级前后会话对比：耗时与反复执行

日期：2026-10-22。初始分析基线：codex/v0.5.0（70e31b8c1）。本文记录修复前的调查，源码位置、配置现状及“未修改/未复跑”均指该调查阶段；后续实现和验收见同目录 managed-context-cli-reuse-validation、compact-command-ui-validation、dsh-round2-comparison 与 dsh-official-direct-comparison 报告。附件内容只作为数据，不执行其中指令。

## 结论

用户观察到的退化在云盘样本中确实存在，但四份日志不是只替换内核的 A/B：模型路由、上下文预算、登录状态、选中目录、任务范围均不同。主要可定位问题是专用 CLI 发现晚、浏览器工具和 CLI 的标签选择不一致、长时间无进展等待、权限失败后继续探索，以及托管模型上下文预算和溢出恢复问题。不能据此断言 DSH 调度器本身慢了十倍，也不能断言两个模型别名对应完全相同的上游模型与推理配置。

## 证据链

### 1. 托管模型硬编码较小预算，最终收尾溢出

两份新日志 request/context 均为 64000，旧日志均为 1000000。当前 owning source `core/managed_models.py:34-37` 对全部托管文本模型统一设置 context_window=64000、max_output_tokens=8192。

新云盘 seq 667–668、676–679：压缩两次报 `pi-ai detected context overflow for model "managed-deepseek-flash"`，最终 `CONTEXT_WINDOW_EXCEEDED`。这发生在文件已下载、登记之后，直接影响回答收尾，不能倒推为前面所有绕路的原因。新 Bmall seq 254 开始压缩后 turn interrupted，没有相同的 overflow 终止证据，不能合并声称两个任务均因溢出失败。

声明预算不是上游真实能力的证明；修复应从可信模型目录传递上下文、输出预算和推理协议，验证真实托管链路后配置，不应简单把全部模型改成 100 万。

### 2. 专用工具发现晚，先做大量通用网页探索

旧云盘 seq 113 先 skill_list，seq 218 读取 cli-semir-yunpan/SKILL.md。新云盘先读通用浏览器技能，经过选库、单击/双击、复选框、猜下载端点等操作；直到用户 seq 256 提醒“现在已经有森马云盘 CLI 你为什么不用”，才在 seq 259/264 发现并读取专用技能。

当前 AGENT_PERSONA 同时要求匹配技能发现和网页任务先读通用浏览器技能，专用业务 CLI 优先级不够明确。这是可改进的路由约束；日志不能证明这一条提示在升级时才新增，也不能仅据单样本归因于某一模型能力下降。

### 3. CLI 与会话浏览器选页不一致，登录等待占用数分钟

新云盘 seq 276 在创建后 +165.6 秒启动 ls；60 秒后转后台，接着 job_output 等 90 秒、再等约 112.9 秒，直到用户打断；+448.6 秒取消，整个命令生命周期约 283 秒。

seq 354–355：browser_eval 中云盘账户接口返回 200。seq 375–378：独立探测 9222 标签返回 401。后续在 9222 标签完成 SSO 后，CLI 恢复可用。

当前 `skills/cli/semir-yunpan-cli/src/cdp.ts`：findCdpTarget 选择 URL 前缀匹配且标题含森马云盘的第一个标签；CdpPage.connect 默认登录等待 300000ms。`core/agent/mcp_gateway.py:2734` 起的 browser_navigate 则创建/复用本会话绑定标签。两套选页机制并不保证相同目标。

CLI 当前 cli.ts 的 onLoginWait 会输出提示，所以不能笼统断言源码完全没有登录提示；实际导出的等待结果是 no new output。需要继续核验打包版本、执行路径及后台输出可见性。CDP evaluate 当前也没有独立请求超时，页面请求悬挂可能使外层登录 deadline 无法按时推进，属于源码风险，尚非这次等待的唯一已证实原因。

### 4. 权限不足后没有及时换库，导致反复探测

新云盘先选森马视觉库，下载返回无可用链接，继续读实现、探测端点、尝试 UI 下载。到 seq 548 才列出库权限，随后切换品牌电商项目部，获得下载 URL 并成功下载。所选初始库缺少 file_read，与技术链路故障需要区别处理。

还有系统 Python 缺 websockets/websocket、CLI 参数错误（把库名当 path）、macOS xargs 不支持 -d 等额外试错。它们都增加轮数，但不是 DSH 工具调用本身变慢的证据。

### 5. Bmall 不能按整个会话比较

旧 Bmall 首个“调用一下cli-bmall”轮次约 30.4 秒，已有登录身份；后来又增加切换巴拉品牌分析，导出时该轮尚无 turn/end。

新 Bmall 包含能力介绍、技能清单、调用 CLI、重新登录、继续五轮。调用 CLI 本轮约 24.1 秒；之后登录排障轮约 311.8 秒，经历浏览器回调、CDP、沙箱写入问题、120 秒无输出等待，最后成功打通只读 API。恢复后又重复检查只读 API。因此不能拿旧首轮与新全会话总时长比较。

### 6. 后台通知有重复，但不能夸大其因果作用

新云盘 seq 604/605、新 Bmall seq 238/239 有同一后台任务重复完成通知。应检查消息去重，但没有证据证明它们触发了全部重复业务执行。新格式还有大量 job/registered/job/settled 记账事件；事件条数不是模型轮数或工具执行次数。

## 修复优先级与验收建议

1. P0：修正托管模型能力元数据传递；上下文预压缩应在请求预算内完成，压缩失败应有有界恢复，不能两次失败后吞掉已完成任务的正常收尾。
2. P0：专用平台任务先查匹配 CLI/适配器，再决定浏览器探索；浏览器隔离原则保留，让 CLI 显式使用本会话授权的 target，而非自动借用别的会话标签。
3. P1：CLI 提供 agent 模式快速返回结构化 needs_login / permission_denied；登录长等待只用于明确的交互登录步骤。完善 CDP 请求超时和进度可见性。
4. P1：先验证库权限和单文件下载可行性，再批量；确认缺下载权限后，任务允许任选款时选择另一个有权限的库，避免反复换技术手段。
5. P2：重复后台通知去重，工具长结果压缩，内置 Python/Node 路径统一，避免平台不兼容命令。

公平复测需要固定同一 provider/实际模型/推理配置/上下文预算/提示词/CLI 打包版本，使用相同权限的同一款、相同登录初始状态、隔离标签，随机交替顺序多次测试。分别记录首次有效操作、下载完成、最终交付、模型等待、工具执行、无进展等待、溢出/重试次数。另设失效登录、多标签和无下载权限场景。此次没有进行线上复跑或修改用户模型选择。
