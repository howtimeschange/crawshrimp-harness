# 供应商模型管理与回归记录 · 2026-10-10

## 本次改动

- 森马海外 OpenAI 默认地址统一为 `https://ai-aigw.semir.com/overseas-openai-codex/v1`，覆盖前端默认值、后端配置、路由和 DSH Web profile。已有显式地址仍按保存值读取。
- 五个内置供应商与自定义供应商均支持模型新增、名称和 ID 编辑、删除、批量 ID 编辑；内置供应商支持恢复预设。预算和推理协议可以逐模型设置。
- 供应商弹窗拆分为“连接配置”和“模型管理”两个 Tab；模型管理采用左侧模型列表、右侧参数详情，并适配窄窗口。
- 新增 `ai.llm.builtin_provider_models`，作为各内置供应商保存后的完整模型列表。未设置供应商键时使用预设，空数组停用该供应商全部模型。公开设置返回只读预设列表 `ai.llm.builtin_provider_model_defaults`。
- 模型列表贯通目录、默认模型选择、会话选择、供应商路由与 DSH 运行时；删除模型后不再出现在目录中。新模型继续使用所属供应商的连接与凭证，未登记模型仍不能通过会话 API 选择。
- 新增 `POST /agent/providers/{provider_id}/discover-models`，支持 DeepSeek 和 GLM。优先读取当前地址的 `/models`；GLM 接口不支持或未返回有效目录时读取官方 `llms.txt` 对话模型目录。鉴权、限流和服务错误直接呈现，不以文档回退掩盖。发现结果只预览，由用户选择导入；草稿 Key 不保存，带 Key 请求不跟随重定向。
- DeepSeek、GLM 新型号的产品 ID 映射到上游 wire ID；GLM FlashX 可发现并导入，未加入固定预设。
- 移除“支持图片”和“支持工具”两个手工勾选项。旧能力标记不再隐藏模型、阻止选择或丢弃图片；工具默认提供，图片通常直接交给当前上游。DeepSeek 官方 V4 Pro 保留原有 Flash 视觉桥接，GLM 官方 5.3/5.2 新增同供应商 Flash 桥接。上下文、输出预算与推理协议仍由程序管理。

这两个能力勾选项是本轮模型编辑界面新增的，最终实现已移除；原有内部 metadata 早已存在。产品层允许图片输入不表示每个上游模型都能识图。DeepSeek 官方 V4 Pro 的底层请求声明保留 `input: [text]`：图片先由同一供应商下的 `deepseek-flash` 识别，再将识别文字交给 Pro 继续回答。产品目录仍允许 Pro 接收图片；用户附件、`read_image` 和 Office/MCP 页图沿用原有桥接。不扩展到国内或自定义供应商的同名 Pro 模型，不借用其他供应商的 Flash 或凭据；官方模型列表需保留 Flash 才能桥接。

## GLM 视觉桥接 · 2026-10-10

官方 GLM 的 `glm-5.3` / `glm-5.2` 使用同供应商、同地址和同凭据下的 `glm-5.3-flash` 识图，再将识别文字交回原模型继续执行，工具定义和工具调用关联保留。用户图片、`read_image` 和 Office/MCP 页图都走这条路径；Flash 自身直接收图。如果用户删除了 Flash，但已导入可识图的 `glm-5.3-flashx`，则使用同供应商 FlashX；两个视觉型号均不可用时明确失败。

新导入的未知官方 GLM 型号先尝试直接收图；只有上游明确拒绝图片、声明仅支持 text，且尚未流出文字、思考或工具活动时，才执行一次 Flash 识图和原模型文本重试。鉴权、限流、服务错误、超时、内容审核与无关的 1210 错误不会触发回退。国内网关和自定义供应商的同名模型不使用官方 GLM 桥接；DeepSeek 原有桥接保留。

使用用户提供的 GLM Key 实测官方接口：Flash 读对随机编号 `256441`、1 个蓝色圆形和 3 个红色方形；5.3/5.2 直接收图均返回 400/1210，错误为 `messages.content.type 参数非法，取值范围 ['text']`。通过实际已安装的 PiAiAdapter 和真实供应商模型目录联调后，5.3、5.2 的用户图以及 5.3 的工具结果图都读对了编号、图形数量和颜色。人为将 5.3 声明为 image 的额外场景也确认了拒图后回退：原模型图片请求 → Flash 图片请求 → 原模型纯文本请求，最终正常完成。

额外实测 5.3 的“图片 → Function Calling → 无副作用本地 echo → 第二轮回答”：原模型以正确编号调用工具，保留原生 replay metadata 后收到了工具结果，最终 `finish.kind = stop`。五个真实适配器场景通过内容与路由校验，证据为 `verified-bridge.json`；原始记录保留在同目录。

相关后端 75 项测试、Node 83 项测试通过，覆盖 GLM 桥接、图片入口、Office/MCP、供应商隔离、单次回退、已有思考/文字/工具输出后禁止重放，以及原有 DeepSeek 兼容。运行时补丁重复应用保持幂等，JavaScript 语法与 Git diff 格式检查通过。

Key 只通过关闭终端回显的 stdin 传入测试进程，没有写入客户端配置、源码、报告或 Git。开发客户端保持运行，重启后加载新的后端声明和运行时桥接。
