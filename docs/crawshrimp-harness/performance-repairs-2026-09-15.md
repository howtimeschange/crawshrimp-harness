# 工作流移除与性能修复 · 2026-09-15

## 结果

已从 Harness 导航、页面挂载和页面源码中移除 **AI 视频工作流、AI 买家秀工作流**，以及只覆盖这两个页面的测试。独立 **AI 生图、AI 生视频** 保留。共享的视频/素材能力和历史任务隔离逻辑仍用于保留功能，因此保留；没有删除用户已有数据。

修复原审查中其余性能问题，并修复提示词库加载时调用不存在的 `ensureSelectedLibrary`。工作流专属的隐藏页面目录轮询随页面删除，不再对其扫描器进行优化。

修改仅在本地工作区，未提交、推送或发布。

## 实现与审查

- **启动**：先创建窗口；通过 Node 工作线程准备数据目录，将目录权限合并为一次 PowerShell 调用。新 token 在父目录保护完成后创建，并单独保护。IPC 和后端启动等待初始化完成；初始化失败显示错误；手动重启也重新等待初始化。Windows 保留专用目录检查、路径连接点检查、精确受保护 DACL 和失败回退。
- **缩略图**：使用已有 Python/Pillow 依赖的异步子进程，单路解码、最多 32 个在途请求；限制 4000 万像素，缓存最多 128 项/16MiB，按路径、文件身份、修改时间、大小和参数区分。移除主线程同步 nativeImage/sips 解码。图片授权仍在 IPC 主进程检查。
- **日志**：每个流最多保留 2000 行/1MiB，注册表最多缓存 64 个流；完整记录以 JSONL 落盘。接口使用 epoch/cursor 增量返回，每页最多 500 行；任务结束前排空有界尾部。页面最多渲染 60 行，读旧日志时避免强制滚到底部；通过流式 HTTP 下载完整日志，下载失败保留已有目标文件。界面不换行，长行可横向滚动。清空操作会清空对应完整日志。
- **任务列表**：清单内容按文件身份/纳秒时间/大小缓存解析，仍扫描成员变化，返回模型副本避免污染缓存；最新运行记录用同一次连接批量读取，每 400 项分块。前端全局轮询和运行状态轮询增加在途保护。
- **测试修整**：启动契约更新为异步初始化顺序；旧 UI 测试补齐 DOM append/消息锚点以及生成配置状态的模拟，保持原有断言，未通过跳过测试消除失败。

## Windows ARM / 8GB 复测

同一 UTM Windows 11 ARM 虚拟机，4 vCPU、8192MiB。分别测试 Electron 43.1.0 x64 转译与原生 ARM64。下表是组件或函数测试，**不是 i3 真机或完整 Windows 安装版验收**。基线见[原审查报告](performance-audit-2026-09-15.md)。

| 场景 | 修复前 | 修复后 |
|---|---:|---:|
| x64 新目录准备 | 26.14s，同步阻塞 | 7.72s，主线程计时器最大间隔 31ms |
| x64 已有目录准备 | 22.30s，同步阻塞 | 3.76s，计时器最大间隔 20ms |
| ARM64 新目录准备 | 6.55s，同步阻塞 | 3.33s，计时器最大间隔 45ms |
| ARM64 已有目录准备 | 4.78s，同步阻塞 | 0.85s，计时器最大间隔 26ms |
| x64 显示 5 万行日志 | 1765ms / 5 万行 DOM | 48ms / 60 行 DOM |
| x64 日志，渲染 CPU 降速 4 倍 | 10566ms | 143ms |
| ARM64 显示 5 万行日志 | — | 41ms；4 倍降速 46ms |
| Windows 300 个任务最新记录查询 | 同轮旧实现 721–914ms | 6–12ms |
| x64 冷缓存 12 张 24MP 图 | 4748ms，同步连续调用 | 3050ms，最大计时器间隔 26ms |
| ARM64 冷缓存 12 张 24MP 图 | 2201ms，同步连续调用 | 3016ms，最大计时器间隔 24ms |

缩略图每组测试创建新缓存，请求经实际新模块的单路队列处理。ARM64 总耗时增加，换取主线程可响应以及受控并发内存；不能把本轮结果描述为所有图片场景吞吐都提高。不同测试的调度、缓存与计时方式存在差异，计时器最大间隔并非所有时刻的 UI 帧时间。

Windows 新日志实现写入 5 万行约 7.97s，尾部保留 528000 字节，初次响应约 134KiB，无新增日志的增量响应 145 字节；完整下载验证为 5 万行。完整日志占用磁盘，清空前会持续保留；本轮没有实现按天自动清理策略。

Windows 权限回读：adapters、adapter-meta、data、logs 和 api-token 均是受保护 DACL，只有当前用户、SYSTEM、Administrators。测试未读出 token 内容。
