# 办公设计与排版

基于 Leonxlnx/taste-skill 的设计原则，针对 Harness 办公运行时改编。来源与改编范围见 `office-design-taste/UPSTREAM.md`。这是设计指导，文件生成和交付仍遵守 `office-common/README.md` 及对应 `office-word`、`office-ppt`、`office-excel` Skill。

## 先确定用途，再选择风格

从用户内容、受众、展示场景和现有模板判断：是会议投屏、屏幕阅读、打印报告还是数据核对。用一句话说明设计方向即可，例如“面向管理层的季度汇报，沿用品牌蓝，以结论标题和大图表为主”。信息足够就直接做；只有不同选择会实质改变交付时才询问。

已有文件先查看实际页面，提取字号、字体、颜色、页边距、页码及表格样式。局部美化沿用品牌和内容结构；不要为了新风格改写事实、删除数据或替换用户指定模板。下述数值是起点，用户模板与明确要求优先。

| 场景 | 排版方向 | 信息密度 |
| --- | --- | --- |
| 管理层汇报、方案决策 | 结论先行，统一网格，一个核心图表配简短解释 | 投屏时少而清楚，细节入附录 |
| 品牌提案、产品介绍 | 继承品牌色，真实产品图片，图文有明确主次 | 留白充分，版式随内容变化 |
| 长篇报告、制度、研究 | 稳定标题层级，正文连续阅读，表格和图注规范 | 允许合理密度，保证检索和打印 |
| Excel 汇报页 | 数据区与摘要区分开，数字对齐，重点克制 | 可核对优先，保留明细 |

## 建立一套可复用的视觉规则

- 先定字体、标题/正文/注释字号、文本与背景色、强调色、页边距和间距。整份文件复用同一组值，不逐页临时选择。
- 中文优先内置“思源黑体”；长文可用“思源宋体”正文搭配黑体标题。实际字体以 `office_runtime_info` 为准；显式设置东亚字体，检查中文、英文、数字和标点是否缺字。不要照搬网页字体清单或临时下载字体。
- 中性底色加一个主要强调色通常足够；品牌有既定配色就继承。图表允许多个分类色，但同一系列跨页颜色一致，并用标签/线型辅助区分，不仅靠红绿颜色。
- 通过字号、字重、对齐和间距表达层级。优先留白分组；边框、阴影、圆角卡片要有信息用途，不给每段文字套装饰框。
- 版式为内容服务：对比用并列、趋势用图表、步骤用流程、细节用表格。避免每页重复“三张等宽卡片”，也不为追求变化打破一致的边距和阅读顺序。
- 图片使用用户素材、可用的授权素材，或按当前请求调用项目已有生图工具；不伪造产品截图、品牌标识或业务证据。图片承担说明作用时配必要图注；不强制每页配图。

## 按格式落实

- PPT：读取 `office-design-taste/references/ppt-layout.md`，再用 `office-ppt` 生成可编辑幻灯片。
- Word：读取 `office-design-taste/references/word-layout.md`，再用 `office-word` 生成具有语义样式的文档。
- Excel：沿用 `office-excel` 的公式、数据、打印与重算规则。日期/金额/百分比用数值格式，数字右对齐；输入、计算和汇总区用清楚的标签及克制的底色区分。不要在原始数据表中为装饰合并单元格，样式调整不能改变公式或统计口径。

只使用现有 Office 工具与内置运行时。脚本通过 `office_run` 执行；内置 Python 由 `CRAWSHRIMP_PYTHON_EXECUTABLE` 指定，不裸跑 python/pip，不因设计任务安装 React、Tailwind、动效包或其他依赖。不要用整页图片替代用户要求可编辑的正文、表格和图表；静态文件无需网页动效。

## 用实际页面完成检查

先 `office_validate` 重新打开原件并核对业务内容，再 `office_render`；按 `office-common/README.md` 逐页 `office_preview_read`，通过 `office_review_record` 记录实际观察。

检查阅读顺序、主次是否清楚、内容是否过密，以及文字截断、重叠、低对比、中文缺字、图表标注、表格跨页和页眉页脚。先修溢出与可读性，再调整装饰。PPT 以整页投屏尺度检查，Word 兼顾完整页面和正文可读性。代码中的尺寸正确不代表实际渲染正确。

发现问题修改源文件，重新渲染并检查新 revision。不得用旧预览或模板截图证明新文件通过；无图像能力时说明尚未视觉检查。交付原件、PDF 和真实检查覆盖，不承诺仅凭本 Skill 就必然达到专业设计质量。
